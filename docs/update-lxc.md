# update-lxc

`update-lxc` brings an LXC up to date with the Git repository: the server commands, the generated
files and `docker-compose.yml`. It is safe to run again and again: when nothing changed, it says so and
does nothing.

```bash
update-lxc --dry-run
```

```bash
update-lxc
```

## What is updated and what is never touched

| Kind | Files | update-lxc |
|------|-------|------------|
| Application (from Git) | `/opt/<game>/docker-compose.yml`, `/opt/<game>/install-server-commands.sh` | replaced after a verified backup; a local change stops the update |
| Generated by the installer | `/usr/local/lib/gameserver/*`, `/usr/local/bin/<commands>`, `gameserver-autoupdate.{service,timer}`, `/etc/profile.d/zz-gameserver.sh`, the block in `/etc/bash.bashrc` | regenerated; a hand edit stops the update |
| User configuration | `/etc/gameserver.conf` | kept; only missing keys are added |
| User configuration | `/etc/gameserver-autoupdate.conf`, `/etc/gameserver-repo.conf` | kept |
| Secrets | `/opt/<game>/passwords.env`, `/opt/<game>/.env` | kept; new keys in the template are reported, not added |
| Game data | every bind-mounted folder in `docker-compose.yml` (e.g. `/opt/<game>/data`, `config`, `game`) | backed up, never changed |
| Backups | `/opt/<game>/backups`, `/var/backups/gameserver` | kept |
| Git clone | `/opt/lxc-gameserver` | fast-forward only; local changes stop the update |

## Steps

1. Read `/etc/gameserver.conf` and `/etc/gameserver-repo.conf` (stops if the LXC was not installed by these scripts).
2. Check that the Git remote and branch can be reached (`git ls-remote`).
3. Clone the repository on the first run, otherwise `git fetch`. It refuses a clone with a different `origin`,
   a different branch than `REPO_BRANCH` (default `main`) or uncommitted changes.
4. Show the current, deployed and target versions. It refuses when the target isn't a fast-forward or doesn't contain update-lxc (no downgrades).
5. Compare every installed file with the target. A file that differs from what update-lxc last
   installed is a **local change**: the diff is shown and the update stops (exit 2) unless you pass `--force`.
   A changed container name, volume or network mode is a **game data migration**, not an
   application update: it stops unless you pass `--allow-volume-change`, and old folders are never moved or deleted.
6. Back up to `/var/backups/gameserver/<time>/`:
   `config.tar.gz` (all configuration, secrets, commands and startup files) and `gamedata.tar.gz` (every
   bind-mounted data folder, or only the savegame with `--saves-only`). Owners, permissions and symlinks are kept
   (`tar --numeric-owner -p`). The backup is verified: `gzip -t`, the archive listing, a check that every data file is
   in it, and `SHA256SUMS`. It stops if there is not enough free disk space. When the compose file changes, the server
   is stopped first so the savegame is consistent.
7. Fast-forward the clone, check the new compose file with `docker compose config`, install the changed files
   (same owner and mode, written to a temporary file and then moved into place) and run the new `install-server-commands.sh`.
8. Start the server again, but only if the compose file changed and the server was running before.
9. Verify: files match the target, commands exist, the generated scripts parse, `passwords.env` and `.env` are
   still there, every game data file from the backup still exists, the container is running, and non-interactive
   shells print nothing. It shows the last log lines.
10. On any failure in steps 7–9 it restores `config.tar.gz` automatically, removes files the failed update created,
    resets the clone to the previous commit and starts the server as it was (exit 3).

Everything is printed and appended to `/var/log/gameserver-update-lxc.log`.

## Options and exit codes

| Option | Meaning |
|--------|---------|
| `--dry-run`, `-n` | Show what would happen; change nothing |
| `--yes`, `-y` | Don't ask before applying |
| `--force` | Replace files that differ locally; your version is kept as `<file>.local-<time>` |
| `--saves-only` | Back up only `DATA_DIR/SAVE_SUB` instead of all data folders (big games, small disk) |
| `--allow-volume-change` | Continue although the compose file moves the game data (move the data yourself first) |
| `--rollback [DIR]` | Restore commands and configuration from a backup (default: the last one) |

| Exit code | Meaning |
|-----------|---------|
| 0 | Updated, or already up to date |
| 1 | Error before anything was changed (no network, missing tool, backup failed) |
| 2 | Stopped because it needs your decision (local change, data migration, wrong branch); nothing was changed |
| 3 | The update failed and was rolled back |
| 4 | The rollback failed: restore by hand with `update-lxc --rollback <DIR>` |

## Rollback

```bash
update-lxc --rollback
```

This restores the files from `config.tar.gz` of the last backup (or `--rollback /var/backups/gameserver/<time>`),
resets the clone to the version from before that update and starts the server again if it is running. Game data is
**not** restored automatically, because that overwrites the world. If you really need it:

```bash
stop
```

```bash
tar -C /opt/<game> -tzf /var/backups/gameserver/<time>/gamedata.tar.gz | head
```

```bash
tar -C /opt/<game> --numeric-owner -xpzf /var/backups/gameserver/<time>/gamedata.tar.gz
```

```bash
start
```

Rolling back to the backup of the very first update-lxc run brings back the old commands. If those didn't
include `update-lxc`, run it from the clone again: `bash /opt/lxc-gameserver/lib/update-lxc.sh`.

## Settings

`/etc/gameserver-repo.conf` (created by the installer if it is missing):

```bash
REPO_URL=https://github.com/klangche/LXC-gameserver.git
REPO_BRANCH=main
REPO_DIR=/opt/lxc-gameserver
BACKUP_ROOT=/var/backups/gameserver
```

Backups are not deleted automatically. Remove old ones in `/var/backups/gameserver` by hand when you
no longer need them.

## First update of an older LXC

An LXC that was set up before update-lxc existed has no `update-lxc` command yet. See
[migrate-existing-lxc.md](migrate-existing-lxc.md).
