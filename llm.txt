# Instructions for an LLM: add a new game to LXC-gameserver

Repo purpose: Proxmox VE host scripts that create an LXC (Debian/Ubuntu) with Docker and a dockerised game server,
plus a uniform set of in-LXC commands. One folder per game: games/<game>/ (lowercase, no spaces, e.g. "valheim").

## Required files in games/<game>/
1. game.conf                  Copy games/valheim/game.conf and change the values: GAME, TITLE,
                               PASSWORDS=("KEY|Label" ...), GAME_CPU/GAME_RAM/GAME_DISK.
                               The root install.sh lists games/ automatically, asks for the game, then runs the
                               community-scripts docker.sh with these resources and installs the game inside the LXC.
2. docker-compose.yml          The server. Must use `env_file: passwords.env`, take the server name from `${SERVER_NAME}`
                               (and `${WORLD_NAME}` if the game has a world name) and publish the game ports.
                               container_name must equal <game>. Bind-mount data under ./ (e.g. ./data).
3. passwords.env               Template: one `KEY=CHANGE_ME` per password. The KEYs must be the env var names the image reads.
4. profile.conf               Copy games/valheim/profile.conf (becomes /etc/gameserver.conf in the LXC):
                               GAME=<game> MODE=docker DIR=/opt/<game> CONTAINER=<game> GAME_LOG (empty = docker logs)
                               DATA_DIR SAVE_SUB (relative to DIR, backed up) SECRETS_FILE=passwords.env
                               APP_ID (empty if the image updates itself) INSTALL_DIR
                               and for auto-update: PLAYER_QUERY (a2s:<query port>[,<port>...] for Steam A2S,
                               minecraft for rcon-cli, empty if unknown), CHECK_APP_ID (Steam dedicated-server app id
                               used to detect new builds, empty = only check for a newer image), VERSION_CHECK
                               (minecraft or empty)
   install-server-commands.sh  GENERATED: run `python3 tools/build-commands.py` after adding profile.conf.
                               Never edit it by hand; shared code lives in lib/.
5. README.md                   Ports, passwords, and the LXC name format.
Also add the game to the table in the root README.md.

## Rules
- Servername is always required: the user can enter one or leave it empty for a random server name from server-names.txt. The LXC name is
  always gameserver-<game>-<servername>.
- Docker is always installed in the LXC (community-scripts docker.sh does this).
- EVERY password/secret the game has (join password, admin password, RCON, role passwords, tokens) must be listed in
  PASSWORDS and passwords.env. They are asked on first launch (empty = random) and editable later with `password` (nano).
- Passwords are limited to A-Z a-z 0-9 _ . @ - (min 5 chars) so they are safe in env files.
- Prefer a maintained Docker image; verify env var names against its documentation.
- Command changes go into lib/ (common.sh, update-lxc.sh, shell-init.sh, installer.sh), then run tools/build-commands.py.
  Commands are files in /usr/local/bin, never aliases or shell functions. Interactive-only output belongs in
  lib/shell-init.sh. Update docs/commands.md and the GS_COMMANDS list in lib/common.sh together.
- Native (systemd+steamcmd) is supported by the commands via MODE=native, but Docker is the default.
- Validate: `python3 tools/build-commands.py --check`, `bash -n`, `shellcheck -S warning`,
  `docker compose -f games/<game>/docker-compose.yml config`, `sudo tests/run.sh`.
- Commit messages/docs in English; the command scripts keep the existing Swedish messages.
